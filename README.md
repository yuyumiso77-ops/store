# 골프웨어 매장 상품 반응 평가

골프웨어 매장별로 상품 사진을 보며 그동안의 **고객 반응, 판매 반응, 장단점, 개선 아이디어**를 상품별로 평가하고,
관리자가 상품별로 모아 분석하는 웹 앱입니다. 외부 패키지 없이 Node.js(18 이상)만 있으면 실행됩니다.

## 실행

```bash
ADMIN_PASSWORD=관리자비번 STAFF_PASSWORD=매장비번 npm start
```

- 매장 평가 화면: http://localhost:3000 (비밀번호 `STAFF_PASSWORD`, 관리자 비밀번호로도 접속 가능)
- 관리자 분석 화면: http://localhost:3000/admin (비밀번호 `ADMIN_PASSWORD`)
- 아이디 칸은 아무거나 입력하면 됩니다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `3000` | 서버 포트 |
| `ADMIN_PASSWORD` | `admin1234` | 관리자 비밀번호 (**꼭 바꾸세요**) |
| `STAFF_PASSWORD` | (없음) | 매장 평가 화면 비밀번호. 비워두면 누구나 접속 가능 |
| `DATA_DIR` | `./data` | 데이터 저장 폴더 (`db.json`) |
| `ANTHROPIC_API_KEY` | (없음) | 넣으면 분석 화면의 **🤖 AI 의견 요약**이 켜집니다 (Claude API, 요약할 때만 호출·결과 저장) |

## 사용 방법

1. 관리자 화면 **상품 이미지로 등록**에서 품목(**어패럴 · 용품 · 골프화 · 장갑**)을 고르고 상품 이미지를 여러 장 올립니다.
   - **파일명 = 품번** 입니다. `GM24-PL101.jpg` → 품번 `GM24-PL101`
   - 처음 보는 품번은 새 상품으로 등록되고(상품명은 품번으로 시작, [수정]에서 변경), 이미 있는 품번은 이미지만 교체됩니다.
   - 이미지는 업로드 전에 브라우저에서 최대 1400px JPEG로 줄여 저장합니다 (원본이 커도 됨, 3장씩 동시 처리) (`DATA_DIR/images`).
   - 파일명이 **PLC 번호**(컬러별 번호, 예: `FJ_42993_sw.jpg`)여도 됩니다. 먼저 `품번,PLC,PLC컬러` 열이 있는 CSV를 올려 두면
     파일명 속 5~6자리 숫자로 상품을 찾습니다. **대표 사진**은 ★로 지정한 사진 > 품번 이름 사진 > 엑셀 첫 번째 컬러의 `_sw` 사진 순으로 정해지고,
     나머지 사진(다른 컬러, `_f`·`_b` 등)은 **상세컷**으로 저장되어 평가 화면에서 넘겨 볼 수 있습니다. 같은 파일명으로 다시 올리면 그 사진만 교체됩니다.
   - **폴더째 끌어다 놓기** 또는 [📁 폴더 선택]도 됩니다 (하위 폴더 포함, OneDrive 동기화 폴더 가능). 이미지·CSV 외 파일은 건너뛰고, 같은 품번이 여러 개면 마지막 파일을 씁니다.
   - **상품 정보 CSV**(첫 줄: `품번,상품명,구분,품목,복종`, 구분 = 남성/여성/남녀공용)를 이미지와 함께 넣으면 상품명·품목이 먼저 등록되고 이미지가 붙습니다.
     이미 있는 품번은 상품명·품목·복종만 수정됩니다. 평가·분석 화면은 **구분(남성/여성) → 복종별로 묶어 정렬**됩니다 (순서는 `server.js`의 `TYPE_ORDER`). 엑셀에서 "CSV UTF-8" 또는 일반 CSV로 저장하면 됩니다.
2. 각 매장은 평가 화면에서 매장명을 입력하고, **상품 사진을 보고 고른 뒤** 그동안 판매하면서 느낀 반응을 평가합니다.
   **매장마다 상품별로 한 번** 평가하며, 같은 상품을 다시 고르면 이전 평가가 채워진 채로 열려 수정할 수 있습니다.
   - 고객 반응 (매우 나쁨 ~ 매우 좋음) → 답에 따라 이어지는 질문(1-1)
     좋음 이상: 좋아한 점(필수) / 나쁨 이하: 아쉬워한 점(필수) / 보통: 둘 중 하나 이상. 반대쪽은 선택으로 추가 가능
   - 1번은 **상품 자체**(디자인·핏·소재 등)에 대한 반응, 2번은 **실제 판매**와 그에 영향을 준 **상품 외 요인**을 묻습니다.
   - 판매 반응 (잘 팔림 / 보통 / 잘 안 팔림) → 판매를 도운 요인 / 판매를 막은 요인 (2-1, 필수: 결품·가격·시즌·진열·직원 추천 등)
   - 분석 화면은 반응과 판매가 엇갈린 상품(반응 좋은데 안 팔림 / 반응 낮은데 잘 팔림)을 따로 표시합니다.
   - 고객들이 좋다고 한 점 / 아쉽다고 한 점 (품목별 항목 + 메모)
   - 자주 찾았는데 없던 사이즈·색상, 개선 아이디어, 주 구매 고객층(연령대·성별, 여러 개)
   - 평가를 마친 상품에는 ✓ 표시가 붙고, 진행률(예: 5/12)이 표시됩니다.
3. 관리자 화면에서 품목별로 걸러 보며 상품별 평균 고객 반응, 판매 반응 분포, 장점·단점·안 팔린 이유·주 구매층 순위,
   없던 사이즈·색상, 매장 의견과 매장별 진행 상황을 확인합니다.
   - 기본은 **표로 보기**(상품 한 줄 요약: 평가 매장 수·평균 반응·판매 반응 막대·주요 장단점·판매 요인)이고, 줄을 누르면 상세 카드가 펼쳐집니다.
   - **정렬**(반응 낮은/높은 순, '잘 안 팔림' 비율 순, 평가 매장 수 순)을 바꾸면 복종 묶음 없이 전체가 한 목록으로 정렬됩니다.
   - 매장 의견은 최신 3개만 보이고 '모두 보기'로 펼치며, 👍/👎/💡 종류별로 걸러 볼 수 있습니다. 매장 진행은 요약 한 줄로 보이고 펼쳐서 매장별로 확인합니다.
4. **CSV 내려받기**로 전체 평가를 엑셀에서 열 수 있습니다.
   - 상품을 고르면 먼저 '이 상품을 평가할 수 있나요?'를 고릅니다. **판매 경험 없음 / 미입고**를 고르면 질문 없이 저장되고(평가 완료로 표시),
     분석의 평균·비율에서는 빠지며 '평가 제외' 건수로 따로 보입니다.
   - **미입고 자동 연동**: 평가를 '미입고'로 저장하면 그 상품의 모든 컬러가 진열 체크 '미입고'로, 진열 체크에서 모든 컬러가 '미입고'면
     평가도 '미입고'로 저장됩니다(정식 평가는 덮어쓰지 않음). 한쪽에서 미입고를 풀면 다른 쪽의 자동 미입고도 지워집니다.
5. **📦 진열 체크 (평가와 별도)**: 평가 화면 위쪽 탭을 '📦 진열 체크'로 바꾸면 매장마다 SKU(품번 × 컬러, PLC)별로
   진열 / 창고 / 없음 / 미입고를 누릅니다(미입고 = 한 번도 안 들어옴, 진열률 계산에서 제외). 누르는 즉시 저장되고 다시 누르면 취소됩니다. 분석 화면의 '📦 진열 현황' 탭에서 SKU별 진열률,
   상태별 매장 목록, 매장별 체크 진행을 보고 '매장 × SKU 표 CSV' / 'SKU별 요약 CSV'로 내려받습니다. (`/?mode=display`로 바로 열림)
5. **⚡ Z-TEC 매장 의견**: 평가 화면 위쪽 카드에서 매장마다 한 번 Z-TEC에 대한 고객 반응, 설명 난이도, 좋았던 점·아쉬운 점·다음 시즌 제안을 남깁니다.
   분석 화면 상단에 응답 매장 수·평균 반응·설명 난이도와 의견 목록이 나오고, `Z-TEC CSV`로 내려받을 수 있습니다.
   - **📈 진열 분석**(진열 현황 탭 → 분석): 진열 × 고객 반응 산점도와 '진열 확대 후보 / 효자 상품 / 진열 재검토' 분류,
     창고에만 있는 SKU, 복종별·매장별 진열률(매장을 누르면 없는·창고만 SKU), 🤖 AI 진열 분석 요약. 기준값은 `server.js`의 `DA`.
6. **🤖 AI 의견 요약**(`ANTHROPIC_API_KEY` 필요): 상품 상세와 Z-TEC 영역에서 버튼을 누르면 매장 의견을 좋은 점·아쉬운 점·요청·검토할 조치로 정리합니다.
   요약은 저장되어 다시 열어도 바로 보이고, 새 평가가 들어오면 '다시 요약'을 안내합니다.
7. **평가 삭제**: 상품 상세의 '📋 매장별 평가 보기 · 삭제'에서 한 건씩, Z-TEC 의견은 각 의견의 🗑로, 매장 데이터 전체는
   '매장별 보기'의 매장 이름 옆 🗑(매장명을 그대로 입력해야 삭제)로 지웁니다. 테스트 데이터 정리에 쓰세요.
8. 평가가 끝난 상품은 **조사 중지**를 누르면 평가 화면에서 빠집니다. 기존 평가는 남습니다.
   잘못 올린 상품은 **삭제**하면 이미지와 그 상품의 평가까지 함께 지워집니다 (되돌릴 수 없음).

### 🎁 사은품 니즈 (매장당 1회, 2026년 전체 기준)
- 매장 화면 **🎁 사은품** 탭 (바로가기 링크 `/?mode=gift`). 매장당 한 번 작성, 다시 저장하면 수정. 임시저장 지원.
- 질문: ① 사은품 문의 빈도 ② 사은품 때문에 구매를 미룬 고객 ③ 올해 사은품의 구매 도움 + 고객 반응(행사 없었으면 생략)·메모 ④ 원하는 사은품(최대 3개)+구체적 품목 ⑤ 적정 기준 금액 ⑥ 매장 아이디어
- **2026 사은품별 반응**: 3번에서 올해 진행한 사은품을 사진 카드로 보여주고, 사은품마다 고객 반응(5단계) 또는 `🚫 증정 안 함`과 메모를 받습니다. 기본 사은품 11개와 사진은 repo의 `gifts/` 폴더에서 처음 실행 시 자동 등록됩니다.
- 관리자 사은품 탭 맨 아래 **⚙️ 2026 사은품 목록 관리**에서 이름 수정, 매장 화면에서 숨기기, 사진 추가·삭제, 새 사은품 추가가 가능합니다.
- 관리자 **🎁 사은품** 탭: 요약 수치, 항목별 분포, 원하는 사은품 순위, AI 의견 요약, 매장 의견(삭제 가능), `사은품 CSV`.
- 매장 참여 탭의 '완료'는 진열·평가·Z-TEC·사은품을 모두 마친 매장입니다.

### 🏬 매장 참여 (조사 대상 매장 명단)
- 관리자 화면 **🏬 매장 참여** 탭 맨 아래에서 `매장코드,매장명,유통사,담당자` CSV를 올리면 조사 대상 명단이 됩니다(올릴 때마다 명단 전체 교체, 입력 데이터는 유지).
- 매장별 진열 체크·상품 평가·Z-TEC 진행률과 상태(미참여/진행 중/완료)를 담당자별로 걸러 볼 수 있습니다.
- **📋 미완료 매장 알림 문구 복사**: 담당자별 미완료 매장 목록을 카톡용 문구로 복사합니다.
- **⚠️ 응답 점검**: 성의 없는 응답이 의심되는 매장을 자동으로 표시합니다. (기준은 `server.js`의 `QA`)
  - 같은 답 반복: 평가 5개 이상 중 80% 이상이 고객·판매 반응이 똑같음
  - 서술 의견 없음: 평가 5개 이상인데 좋은 점·아쉬운 점·개선 의견을 하나도 안 씀
  - 너무 빠른 평가: 상품 하나 평가 간격이 보통 15초 미만
  - 평가 제외 많음: 절반 이상을 '판매 안 함'·'미입고'로 넘김
  - 진열 체크 일괄 입력: 20개 이상 중 95% 이상이 같은 값
  - **답변 보기**로 그 매장이 입력한 답(입력 시각 포함)을 바로 확인할 수 있습니다.
- 매장 화면의 매장명 칸은 명단에서 자동완성되고, `롯데잠실점`·`롯데 잠실` 처럼 입력해도 공식 이름(`롯데잠실`)으로 맞춰집니다. 명단에 없는 이름은 경고가 뜨고, 관리자 탭에 "명단에 없는 이름"으로 따로 표시됩니다.

### ✏️ 임시저장
- 상품 평가·Z-TEC 의견을 쓰다가 저장 전에 나가도, 같은 기기·브라우저로 다시 들어오면 쓰던 내용이 채워집니다(브라우저 localStorage, 매장명+상품별).
- 작성 중이던 상품은 다시 들어오면 자동으로 열리고, 상품 목록에 `✏️ 작성 중` 표시가 붙습니다. 저장하면 임시저장은 지워집니다.
- 임시저장은 그 기기에만 있고 서버로 제출되지 않습니다. 저장 버튼을 눌러야 본사에 집계됩니다.

## Railway 배포

1. https://railway.com 에 GitHub 계정으로 로그인합니다.
2. **New Project → Deploy from GitHub repo → `store`** 를 선택합니다.
   (저장소가 안 보이면 *Configure GitHub App*에서 `store` 접근을 허용하세요.)
3. 서비스의 **Variables** 탭에서 아래 두 값을 추가합니다.
   - `ADMIN_PASSWORD` = 관리자 비밀번호
   - `STAFF_PASSWORD` = 매장용 비밀번호 (평가 화면 접속용)
   - `DATA_DIR` = `/data`
4. 서비스를 우클릭(또는 ⌘K) → **Attach Volume** → Mount path에 `/data` 를 입력합니다.
   이 볼륨이 있어야 재배포해도 응답이 지워지지 않습니다.
5. **Settings → Networking → Generate Domain** 을 누르면 `https://….up.railway.app` 주소가 생깁니다.
6. 그 주소 + `/admin` 으로 들어가 상품을 등록하고 QR을 인쇄하면 끝입니다.

이후 `main` 브랜치에 push하면 Railway가 자동으로 다시 배포합니다.

장단점 항목·미구매 이유 등 선택지는 `server.js` 상단의 `CATEGORY_ASPECTS`, `OPTIONS`에서 바꿀 수 있습니다.
